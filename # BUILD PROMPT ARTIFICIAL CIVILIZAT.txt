# BUILD PROMPT: ARTIFICIAL CIVILIZATION SIMULATOR

You are the lead architect and senior software engineer responsible for building a persistent, emergent civilization simulation.

Build the system described below as a real, working application — not a mockup, prototype full of placeholders, or collection of disconnected demonstrations.

The finished product should feel like:

> “I created a world, released civilizations into it, and watched history happen.”

It should NOT feel like:

> “I entered parameters and received a numerical result.”

The simulation must be:

* Emergent
* Persistent
* Explainable
* Reproducible
* Deterministic when given the same seed/configuration/version
* Computationally efficient
* Modular
* Debuggable
* Observable
* Capable of extremely long simulations
* Capable of producing unexpected historical outcomes
* Capable of supporting very large populations without simulating every person at maximum detail

Do not script historical outcomes.

Create the systems, incentives, constraints, opportunities, and feedback loops that allow history to emerge.

---

# 1. CRITICAL ARCHITECTURAL REQUIREMENT

## Hybrid persistent-individual architecture

Every human must conceptually exist as a persistent individual with:

* Unique ID
* Generation
* Age
* Sex
* Health
* Personality
* Intelligence
* Skills
* Wealth
* Job/occupation
* Needs
* Relationships
* Family
* Beliefs
* Political beliefs
* Memory
* Goals
* Reputation
* Location
* Knowledge
* Inventory
* History
* Civilization affiliation
* Settlement affiliation where applicable

However, DO NOT fully simulate every individual every tick when populations become large.

Separate:

### Agent existence

Whether the individual exists in the simulated world.

from:

### Agent simulation resolution

How much computational attention is spent simulating that individual.

Every individual remains persistent even when simulated at low resolution.

Agents must be able to transition dynamically between:

LOW → MEDIUM → HIGH resolution

without losing:

* Identity
* Relationships
* Attributes
* Memories
* Knowledge
* Family
* Location
* History
* Reputation
* Ownership
* Political status

The observer must be able to locate and inspect an individual even if that individual is currently low-resolution.

# 3. COMPUTATIONAL EFFICIENCY IS A CORE REQUIREMENT

Optimize for simulation throughput.

Do not waste CPU cycles on meaningless microscopic actions.

Use:

* Discrete simulation ticks
* Aggregated population calculations
* Adaptive-resolution agents
* Event compression
* Important-event logging
* Periodic state snapshots
* Lazy calculations
* Cached derived values
* Spatial partitioning
* Efficient lookup structures
* Batched population calculations
* Dirty-state updates
* Priority queues where appropriate
* Incremental recalculation
* Deterministic seeded randomness
* Background/noncritical calculations where safe
* Historical event summarization
* Automatic pruning/compression of insignificant events

Do not generate an event for every trivial action.

Example:

Do NOT log:

> Agent 381 picked up one piece of wood.

> Settlement harvested 4,812 units of wood during Year 38.

# 66. IMPLEMENTATION RULES

When implementing:

1. Inspect the existing codebase before rewriting it.
2. Preserve working functionality.
3. Do not rewrite stable systems unnecessarily.
4. Do not create duplicate systems.
5. Refactor only where it improves architecture.
6. Keep modules loosely coupled.
7. Use interfaces/contracts between systems.
8. Avoid global state where possible.
9. Make configuration data-driven.
10. Make constants configurable.
11. Make simulation behavior testable.
12. Make randomness deterministic.
13. Keep UI separate from simulation logic.
14. Keep persistence separate from simulation logic.
15. Never require an external AI API for core simulation.
16. Never hide failed implementation behind UI placeholders.
17. Never claim a feature works until it is actually implemented and tested.
18. Add tests as features are added.
19. Prefer simple deterministic algorithms over expensive AI calls.
20. Optimize only after correctness, but design for scalability from the beginning.

# 67. MOST IMPORTANT DESIGN PRINCIPLE

The simulator is not supposed to simulate every microscopic human action.

It is supposed to simulate the SYSTEMS that make billions of humans possible.

Every human remains a persistent individual.

Computational resolution determines how deeply that human is simulated at a given moment.

This distinction is fundamental.

Do not sacrifice individual identity merely to gain performance.

Do not sacrifice performance by deeply simulating every individual every tick.

Use adaptive resolution to achieve both.
